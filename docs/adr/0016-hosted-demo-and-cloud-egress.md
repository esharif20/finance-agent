# The hosted demo is a separate, synthetic-only process, and the local app gains one cloud host

The public demo runs as its own process (`FA_DEMO=1`) on Vercel at the default `*.vercel.app` address, with no custom domain. It holds synthetic ledgers only, each visitor's in `FA_DEMO_DIR`, in plain SQLite: no Keychain, no card art, no sync or import, no Ollama and no cloud. Visitors get anonymous sessions in a signed cookie that carries only a visitor id and a Persona. Its one egress is the optional GitHub login from `demo.auth`. ADR 0003 still holds: no real data and no multi-user real data. The local app gains one egress host, `generativelanguage.googleapis.com` (Google Gemini), pinned in config and reached only from `gateway.cloud` under ADR 0011, with the API key in the Keychain under its own service name and never set on Vercel. The gateway may carry redacted real data, so it starts only when the key belongs to a billing-enabled (paid) project, checked at startup; on the free tier Google may use prompts to improve its products. Synthetic-only work (data generation, the benchmark, the judge) may use either tier. Gemini Flash writes gateway wording and synthetic data, and Gemini Pro is the judge; model ids live in config. Spend is metered in `spend.sqlite`, which holds no personal data, under the £9 cap of ADR 0013. The trade-off is a second process and one more audited host in return for a demo that cannot reach real data by construction, and cloud prose that is only as private as the placeholders and the paid-tier rule make it. Any further host needs a new ADR.
